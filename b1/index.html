STEP 1 · PLAN

規劃：先問對問題，不要先問「幫我做」

要解決誰的問題？

先定義使用者：他在什麼情境、想完成什麼事。

要達成什麼？

一個產品先解一個核心問題，貪多一定失焦。

手上有哪些素材與限制？

資料、時間、工具，決定第一版能做到哪裡。

THE RUNNING PRODUCT

主線登場：2000 高頻單字 App

它要解決誰的問題

想準備英檢、加強職場英文，卻沒時間、背了就忘的人。

為什麼用它當範例

需求單純、人人都懂英文學習、資料好準備，最適合完整走一次流程。

STEP 2 · DEFINE · 產品定義書

需求：產品定義一句話講清楚

為 目標使用者，在 使用情境 中，解決 核心問題。
透過 主要功能，讓使用者達成 可衡量成果。

範例：為準備英檢與職場英文的學習者，提供每日 10 分鐘的 2000 高頻單字練習，讓他們能追蹤熟悉度並持續複習。
STEP 2 · DEFINE · User Story

用 User Story 說清楚「誰、要什麼、為什麼」

身為 〈角色〉，我想要 〈做某件事〉，以便 〈得到某價值〉。
  • 身為上班族學習者，我想要每天只練 20 個高頻單字，以便利用通勤零碎時間持續進步。
  • 身為準備英檢的人，我想要系統自動把答錯的字排進複習，以便把時間花在還不熟的地方。
  • 身為想看到成效的使用者，我想要看到熟悉度百分比，以便知道自己還差多少。

每個故事再補一句驗收條件：怎樣算完成？例：答錯的字，隔天一定出現在複習清單。

STEP 2 · DEFINE · 功能規格表

把故事拆成一張功能規格表

功能使用者可以…規則 / 狀態優先
每日單字看今天的 20 張單字卡每天預設 20 字，可在設定調整P0
測驗做四選一、看即時對錯答錯自動排進複習清單P0
複習重測錯題直到答對連續答對 3 次 → 標記為熟悉P1
進度看已學 / 待複習 / 已熟悉數量依狀態統計，每日更新P1
設定調整每日字數與提醒時間每日字數範圍 10–50P2

P0＝MVP 必做、P1＝接著做、P2＝有空再做。優先度讓你知道先做什麼。

STEP 3 · DESIGN

先分清楚：定義 vs 設計

定義：要有什麼

系統要存哪些資料、要做哪些事。對應資料模型與功能規格。

設計：怎麼組起來

資料、邏輯、畫面怎麼分層，狀態怎麼流動，操作怎麼跑一遍。

今天的「設計」＝架構圖 ＋ 資料模型 ＋ 狀態流 ＋ 畫面示意，四張攤開就是一份可交付的架構。

STEP 3 · DESIGN · 架構圖

三層式架構：畫面、邏輯、資料

畫面層　看得到、點得到的

首頁單字卡測驗頁複習頁進度頁設定頁
▼ 使用者操作　　　▲ 畫面回應

邏輯層　背後的規則

每日選字判斷對錯錯題複習更新熟悉度統計進度
▼ 讀取 / 寫入　　　▲ 回傳資料

資料層　存起來的東西

單字中文解釋例句程度學習狀態答題紀錄

走一次：按〔送出答案〕→ 畫面層送出 → 邏輯層判對錯、更新熟悉度 → 資料層寫入紀錄 → 回畫面層更新進度。

STEP 3 · DESIGN · 資料模型

資料層長什麼樣？先定資料結構

// 內容：單字本身（大家共用）
{ "id": 1, "word": "abandon", "pos": "v.",
  "zh": "放棄；拋棄",
  "example": "Don't abandon your plan.",
  "level": 1 }

// 狀態：每個人的學習進度
{ "wordId": 1, "status": "學習中",
  "wrongCount": 2, "lastReview": "2026-08-04" }
  • 把資料切成「內容」（單字本身）與「狀態」（每個人的進度）兩種。
  • 內容大家共用；狀態每個使用者一份。
  • 資料結構定了，邏輯層才有東西可以算。
STEP 3 · DESIGN · 狀態流

狀態怎麼流動？畫出狀態機

未學學習中待複習已熟悉
  • 未學 →〔開始學習〕→ 學習中
  • 學習中 →〔連續答對 3 次〕→ 已熟悉 ✅
  • 學習中 →〔答錯〕→ 待複習
  • 待複習 →〔重測答對〕→ 學習中

規則寫死，AI 才不會亂猜——這就是邏輯層要實作的東西。

DESIGN · UI/UX 原則

畫示意時，守住四個 UX 原則

視覺層級

最重要的先被看到——今天要背的字最大、最顯眼。

留白聚焦

一頁一個主要任務，別把功能全塞在同一畫面。

即時回饋

答對、答錯、標記熟悉，畫面要馬上有反應。

一致性

同樣的東西長一樣、放一樣的位置，使用者不用重學。

MATERIALS · 素材清單

2000 單字素材怎麼取得？

  • 字表：使用 NGSL 高頻英文字表，完整約 2800 字，第一版取前 2000 字。
  • 欄位：整理成 CSV 或 JSON——單字、中文解釋、例句、詞性、級別。
  • 補充：中文解釋與例句可請 AI 產生，但要抽樣校對，避免錯義或怪例句。
  • 匯入：前端原型先用 JSON；正式產品再接資料庫或後台管理。
